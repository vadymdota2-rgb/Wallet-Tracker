# Wallet Tracker — мини-апп

Telegram-мини-апп над сканером **WhaleScanner**. Всё, что видит человек, —
здесь: кошельки, рейтинг, аналитика, дайджест, премиум, настройки. Меню в
чате бота больше нет: на любое сообщение бот отвечает кнопкой «Открыть
приложение», а в чат приходят только алерты и подтверждения оплаты.

## Что внутри

```
src/i18n/       16 языков × 851 ключ, собираются tools/sync-i18n.py
src/lib/        запросы, форматирование, свечи, разбор серверных подписей
src/store/      состояние: сохраняемое (app) и живое (live)
src/components/ строка, плитки, кнопка, логотип монеты, графики, тосты
src/screens/    вкладки и экраны стека
src/styles/     тема, сброс, правила приложения
tools/          словарь tools/i18n.json и его сборка, проверки guard.py
whale_api.py    JSON API поверх whale_bot.db и hyperliquid.db
wt_shield.py    щит API: размер тела, соединения, тайм-ауты, баны, логи без секретов, TLS
wt_digest_img.py картинка выпуска на сервере (Pillow) — автопостинг в Telegram-канал
fonts/          IBM Plex Sans для этой картинки (OFL)
nginx.conf      статика, прокси к API и к биржам, кэш логотипов
fetch_logos.py  разовая выкачка логотипов в html/coins/
```

## Разделы — как в боте

| Бот | Мини-апп |

| 📊 Аналитика | вкладка «Аналитика»: поток, крупнейшие сделки, ликвидации, фандинг, ротация |
| — | вкладка «Дайджест»: выпуск за сутки, последние 30, лайки и комментарии (в боте такого раздела нет) |
| 💰 Порог алертов | экран порога: пресеты бота и своя сумма |
| ⭐ Премиум | экран премиума и переход в чат за оплатой |

Подписку покупают и здесь, и в чате: звёздами Telegram или в USD₮ сети TON.
Подробности — в разделе «Оплата премиума».

## Как запустить

### Локально, посмотреть глазами

```bash
npm install
npm run dev            # http://localhost:5173
```

Dev-сервер отдаёт только статику, поэтому `/api`, свечи и логотипы он
проксирует на уже выкаченный адрес — ни nginx, ни баз бота поднимать не
нужно. Свой адрес: `WT_PROXY=https://… npm run dev`.

Подписи Telegram в обычном браузере нет, поэтому приложение переходит на
публичный `/api/market`: рынок, топ трейдеров, сигналы и графики видны,
свои кошельки и порог — нет. Чтобы увидеть личные данные, открой мини-апп
из чата с ботом.

### Собрать

```bash
npm run typecheck
npm run build          # результат в html/
```

`build` идёт строго по порядку: проверка типов → очистка → сборка. Очистка
стоит после `tsc` намеренно: иначе ошибка типов оставляла бы `html/` пустым —
файлы прошлой сборки уже удалены, новые ещё не собраны. Без этого файлы прошлых сборок копились бы: имена содержат хеш,
поэтому новая сборка не перезаписывает старую, а ложится рядом. `html/coins`
очистка не трогает — там 1547 логотипов, которые сборка не создаёт.

Отдельно очистку можно позвать как `npm run clean`.

Номер сборки берётся из `BUILD_NUMBER`, иначе подставляется дата.

`emptyOutDir` выключен намеренно: в `html/` лежит `coins/` — 1547 логотипов
на 26 МБ, сборка их не трогает.

Имена файлов содержат хеш. Это не украшение: nginx отдаёт `/assets/` как
неизменяемые на год, и прежняя сборка без хешей приводила к тому, что после
выката браузер брал новый `app.js` вместе с прошлогодним `routes.js` и падал
с «Unexpected end of input».

### Словари

```bash
python3 tools/sync-i18n.py
```

Собирает `src/i18n/*.ts` из `tools/i18n.json`: ключ, под ним шестнадцать
языков. Меню в чате больше нет, и словарь приложения от бота не зависит —
бот хранит только тексты алертов. Скрипт падает, если для ключа не заполнен
хоть один язык.

Словари объявлены как `Record<DictKey, string>`, а не `Partial`: пропустишь
ключ — сборка встанет и назовёт его. В прошлой версии они были `Partial`,
недостающее молча подменялось английским, и арабский жил с 29 ключами из 427.

### Логотипы

```bash
python3 fetch_logos.py
```

Кладёт `coins/bsc/<checksum>.png` и `coins/hl/<имя>.svg`, пишет
`coins_manifest.json`. Папка едет в репозиторий как `html/coins/`, манифест
остаётся рядом с `whale_api.py`: по нему API понимает, какие файлы есть, и
не предлагает браузеру ходить наружу. Перезапустив выкачку, обнови и то, и
другое — иначе API начнёт указывать на несуществующие файлы.

```bash
python3 tools/sync-coin-logos.py
```

Собирает `src/components/coin-logos.ts` — тикер → адрес логотипа на
CoinGecko, через наш же `/cglogo/`. Нужен монетам, которых нет ни в образе,
ни у Hyperliquid: на BingX и Gate торгуется впятеро больше тикеров, и без
этого списка половина строк фандинга — буквы в кружках. Выверенные вручную
адреса лежат в `coin-fallback.ts` и главнее собранных.

Цепочка перебора в `CoinIcon` идёт от точного к общему: файл из образа →
рисунок площадки → монета по тикеру → биржевой логотип. Рынки HIP-3
(`xyz:NVDA`, `para:TTWO`, `mkts:GOLD`) Hyperliquid раздаёт по точному имени,
и приставка у него строчная: `XYZ:SMSN.svg` отдаёт не картинку, а страницу
приложения — с кодом 200, так что на ошибку это даже не похоже. Если своя
площадка рисунка не выложила, берётся рисунок `xyz` — самой большой из них.

Акции последним звеном идут через `/stlogo/` (`assets.parqet.com`): их на
биржах уже десятки — у Hyperliquid как рынки HIP-3, у остальных обычными
тикерами (AMZN, TSLA, QQQ, MCD). До этого звена доходят только строки, у
которых не нашлось ни файла, ни рисунка площадки, ни монеты с таким
тикером. Плата — редкая ошибка: у монеты с коротким именем, похожим на
биржевой код, окажется логотип компании. Известные совпадения разобраны
вручную в `coin-fallback.ts`: HEI — это Heima, а не HEICO, BTR — Bitlayer,
WEN — мемкоин; у природного газа (NG) логотипа нет ни у кого, и там честнее
оставить букву, чем показать золотодобытчика с тем же кодом.

На живой выгрузке из 231 инструмента логотип находится у 204; было 120.

### Оплата премиума

Подписку покупают прямо в приложении: звёздами Telegram и в USD₮ сети TON.
Оплаты монетой TON (она же GRAM по курсу) больше нет нигде — ни в чате, ни в
приложении: цена в долларах равна цене в USD₮, и курс, которого могло не
быть, из расчёта ушёл вместе с ней.
Своей выдачи подписки в API нет намеренно — она уже написана в `premium.cpp`
бота и должна остаться в одном месте: там продление срока, запись платежа в
историю и уведомление в чат.

Звёзды. Счёт создаёт API (`createInvoiceLink` с той же нагрузкой и суммой,
что выставляет бот), окно оплаты открывает Telegram, подтверждение платежа
приходит боту в `getUpdates` — и подписку выдаёт он, как при покупке из чата.

USD₮. Счёт кладётся в таблицу `ton_invoices` бота с пометкой `kind='usdt'`,
человек переводит деньги на тот же кошелёк, что и в чате, с памяткой в
комментарии. Адрес берётся так же, как в `tonWallet()` из `premium.cpp`:
переменная `TON_WALLET_ADDRESS`, а без неё — тот же адрес по умолчанию. У
бота и у API разные службы, и требовать переменную только здесь значило бы
оставить приложение без кнопки оплаты на ровном месте. Дальше а приход видит опрос бота `pollUsdtPayments` — он сверяет
мастер-контракт USD₮, занимает счёт одним обновлением и выдаёт подписку.
Перевод из приложения подписывает кошелёк через TON Connect; рядом с кнопкой
показаны адрес, сумма и памятка — кошельком, который TON Connect не знает,
платят руками.

Тело перевода жетона собирается в `src/lib/ton.ts` без библиотек: нужна одна
ячейка без ссылок, а `@ton/core` весит сотни килобайт. Сборка сверена с ним
байт в байт — `node tools/ton-boc-check.mjs`, он же стоит только для этой
проверки и в сборку приложения не входит.

Пока бот не перезапущен с поддержкой USD₮, приложение кнопку не показывает:
признак — столбец `kind` в его таблице счетов. Иначе счёт выставился бы,
деньги ушли, а выдать подписку было бы некому.

### Фандинг

Ставки берутся с двенадцати площадок: Hyperliquid — из своей базы (её
наполняет бот), остальные — запросами наружу, своим потоком раз в десять
минут. Поэтому машине с API нужен исход на `fapi.binance.com`,
`api.bybit.com`, `www.okx.com`, `api.bitget.com`, `open-api.bingx.com`,
`api.gateio.ws`, `api.mexc.com`, `api-futures.kucoin.com`,
`futures.kraken.com`, `api.international.coinbase.com`, `fapi.asterdex.com`,
`api.coingecko.com` и `toncenter.com` (жетонный кошелёк плательщика).

Карте ликвидаций, кроме того, нужны история открытого интереса и свечи
Binance, OKX, Bybit, Gate, HTX и dYdX и снимки интереса ещё двух десятков
бирж — среди них `openapi.blofin.com` и `fapi.xt.com`. Binance и Bybit
закрыты для некоторых стран (ответ 451 и 403): проверить машину —
`curl -s -o /dev/null -w "%{http_code}" https://fapi.binance.com/fapi/v1/ping`.

Домен фьючерсов MEXC (`contract.mexc.com`) отказывает облачным адресам, тот
же API отдаёт `api.mexc.com` — по нему и ходим. Размер контракта нужен там,
чтобы перевести открытый интерес в доллары; выгрузка на два мегабайта
держится шесть часов, а не тянется каждый круг.

Binance и Bybit отказывают облачным адресам (`451` и `403`) — и с нашей
машины их собственный API недоступен. Для них есть запасной источник:
доска деривативов CoinGecko, те же пары со ставкой, открытым интересом и
оборотом. Чего там нет — шага выплат и времени следующей: у обеих бирж по
умолчанию восемь часов, отсчёт идёт до ближайшей границы 00/08/16 UTC, и
для пар с другим шагом время приблизительное. Точные значения приходят
только там, где доступен API самой биржи. Площадка, которая не ответила и
не имеет запасного источника, просто не появляется в приложении.

Перекосы отдаются все: в общей выгрузке лежит первая страница каждой доски,
остальные достаются `/api/fund?ex=&offset=&limit=` из тех же готовых досок,
что обновляет фоновый поток. Ставки приводятся к суточным — только ими
биржи и сравнимы: Hyperliquid, Kraken, Coinbase и Aster платят каждый час,
OKX, Gate, Bitget, MEXC и KuCoin — раз в час, четыре или восемь, у каждой
пары свой шаг, и он приходит в ответе; остальные раз в восемь.

Площадки выбираются лентой, а не сеткой плиток: двенадцать плиток занимали
пол-экрана, и список строк, ради которого раздел и открывают, уезжал вниз.
В ленте выбранная площадка стоит в середине и в полный размер, соседние
мельче, а выбор идёт за прокруткой — но не на каждый пиксель, а когда лента
остановилась: иначе, пока палец ведёт от Binance к Bybit, приложение успело
бы сходить за двумя лишними досками.

Лента кольцевая: список повторён копиями, и когда прокрутка уходит из
средней, положение молча переносится в неё же — карточки в копиях
одинаковые, подмены не видно, а края, в который лента упиралась, больше
нет. Копий тем больше, чем короче список: одного сильного маха должно не
хватать, чтобы долететь до конца. Подсвечена ровно одна карточка — та, что
в середине: на коротком списке две копии одной площадки попадают на экран
разом, и подсветка по названию зажигала бы заодно и боковую.

### Бесплатная неделя и удаление данных

Неделя премиума выдаётся один раз на аккаунт — по строке в `trial_granted`.
Эта строка единственная, что переживает «удалить мои данные»: и `forgetUser()`
бота, и `mutate('forget')` здесь стирают всё остальное, но не её. Пока она
удалялась вместе с профилем, цикл «удалил данные → /start → снова семь дней»
работал без конца. В строке нет ничего, кроме chat_id и даты выдачи, и об
этом сказано и в политике конфиденциальности, и в предупреждении перед
удалением.

Новый аккаунт Telegram — это новый chat_id, и неделю он получит. Без
привязки к телефону или к платежу это не лечится ничем, что у нас есть.

### Хранилище на устройстве и самоочистка

Запасные ответы сервера и настройки экранов лежат в `localStorage` под
ключами `wt-…`. Раз за запуск, через четыре секунды после отрисовки,
`sweepStorage()` (`src/lib/storage.ts`) убирает за приложением: ключи `wt-…`,
которых нет в списке `KEEP` (старые версии, убранные разделы), записи
запасов старше месяца, прошедший отсчёт халвинга и время правки рисунков у
монет без рисунков старше трёх месяцев. Чужие ключи не трогаются. Новый ключ
обязан попасть в `KEEP`, иначе его сотрёт при следующем запуске, — это
проверяет `tools/guard.py`.

### Отсчёт до халвинга

Отдельный модуль; в общих файлах — только подключение:

| Часть | Файл |
|---|---|
| Сервер: источники, кэш, фон, бюджет времени, пауза после сбоя | `wt_halving.py` |
| Тип ответа, проверка, расчёт | `src/lib/halving.ts` |
| Карточка и её стили | `src/components/HalvingCard.tsx`, `HalvingCard.css` |
| Запрос и запас на устройстве | `fetchHalving` в `src/lib/api.ts` (там все запросы) |
| Тесты | `tests/test_halving_api.py`, `tests/test_halving_security.py`, `tests/test_halving_fuzz.py`, `tests/halving.test.ts`, `tests/halving.props.test.ts`, `tests/tick.test.ts`, `tests/e2e/halving.e2e.test.ts` |
| Образец ответа — договор приложения и сервера | `tests/fixtures/halving.json` |

Внизу бокового меню, у всех, с Премиумом и без (`/api/halving` открыт:
данные блокчейна общедоступны). Сервер берёт высоту и время последнего блока
у mempool.space и считает дату по среднему времени блока за всю эпоху от
прошлого халвинга — не за текущий период сложности: тот гуляет на ±5 % и,
растянутый на полтора года, сдвигал дату на недели. Ответ живёт 5 минут,
устаревший отдаётся сразу, а свежий собирается в фоне; если все источники
молчат, минуту сервер отвечает «нет данных», не пытаясь снова.

Расчёт в приложении — `src/lib/halving.ts`, без React и сети: проверка
ответа (`validHalving`), награда как в консенсусе (`50 BTC >> эпоха` в
сатоши), поправка на часы телефона по времени сервера (`now` в ответе) и всё,
что рисует карточка (`halvingView`). Тесты: `npm test` — `tests/*.test.ts`
(node --test; нужен Node 22.18+, он сам снимает типы TypeScript) и
`tests/test_halving_api.py` (unittest, сеть подменена); `tools/guard.py`
гоняет их сам.

**Инварианты** — правила, которые обязаны выполняться при любых входных
данных. Их проверяют тесты свойств на тысячах случайных входов
(`tests/halving.props.test.ts` — 120 000 случаев, `tests/test_halving_fuzz.py`
— 3 000 «сетей» с мусором; генераторы с фиксированным зерном, нарушение
воспроизводится по номеру случая):

1. Остаток до халвинга — целые секунды ≥ 0; дни·часы·минуты·секунды
   раскладывают его без потерь (часы < 24, минуты и секунды < 60).
2. Высота — внутри эпохи; номер блока халвинга — тогда и только тогда,
   когда остаток 0.
3. Полоса — от 0 до 100 %; подпись до халвинга не больше 99,9 %.
4. Награда — `50 BTC >> эпоха` в сатоши; следующая — ровно половина с
   отбрасыванием, как в сети.
5. С ходом времени остаток не растёт, высота и полоса не убывают.
6. Мусор на входе не роняет проверку; пропущенное ею не даёт NaN и не
   ломает формат даты.
7. Сервер на любом ответе сети не падает; его ответ «ok» соблюдает границы
   (высота правдоподобна, среднее 480–720 с или ровно 600, время блока не
   из будущего, eta ≥ tip) — и приложение принимает каждый такой ответ
   (проверяется запуском его `validHalving` через Node).
8. Поля ответа сходятся между собой: интервал — ровно 210 000 блоков
   (правило сети); последний блок — не старше суток и не дальше 2 часов
   вперёд от времени ответа; eta — от последнего блока по среднему (запас —
   сутки). Подделку, где каждое поле правдоподобно, а вместе — нет
   (отсчёт на 70 лет при высоте 2026 года), приложение не показывает.

Свёрнутое приложение сервер не спрашивает; вернулись — свежий ответ сразу,
а не через пять минут.

Подписи под числами и фраза для читалки экрана — из Intl (CLDR), в
правильной форме слова для числа и языка: «1 day / 2 days», «1 dzień /
544 dni», «544 يومًا», «544 дня 3 часа 45 минут 23 секунды». Словарь
(`hv_d` … `hv_s`) — запасной путь для WebView без Intl единиц.

**Модель угроз.** От чего модуль защищён: сломанный или подменённый
источник (абсурдная высота, время, среднее, мусорные байты, кривой хеш,
огромный ответ, перенаправление на чужой адрес, «бесконечные» числа — см.
таблицу атак ниже); зависший источник (бюджет 20 с, пауза минуту после сбоя);
поток запросов (кэш один на всех, nginx 120/мин на человека); испорченные
данные на телефоне (проверка при чтении, уборка); неверные часы телефона
(поправка по серверу); падение карточки (предохранитель). Чего модуль не
обещает: точной даты — это оценка по среднему, отсюда «≈»; защиты от
источника, который врёт правдоподобно и согласованно (сверка нескольких
независимых источников — возможное развитие).

Типы: `wt_halving.py` — `mypy --strict` (ответ — `TypedDict Reply`, тот же
договор, что `HalvingReply` в приложении); файлы модуля в приложении —
строжайший TypeScript (`npm run typecheck:halving`: exactOptionalPropertyTypes,
noImplicitOverride, noPropertyAccessFromIndexSignature, noImplicitReturns).
Сервер проверяется на Python 3.10–3.13.

Качество тестов меряется двумя способами. Покрытие — 100 % строк и ветвлений
у `wt_halving.py`, `src/lib/halving.ts` и `src/lib/tick.ts`
(`python3 -m coverage run --branch …`, `node --test --experimental-test-coverage`).
Мутационная проверка — `python3 tools/mutate-halving.py`: 68 порч кода
(границы, знаки, константы, защиты от атак, гонки, таймер секунд, формы слов), тесты
убивают все 66 значимых; две мутации эквивалентны (не меняют ничего
наблюдаемого) и не считаются. Гонять после любой правки модуля; идёт и в CI.

**На любом устройстве.** Иконка — векторная (SVG), шрифт — IBM Plex Sans
до 700, поэтому на экранах ×2 и ×3 всё резкое. Браузерный тест проверяет,
что ничего не вылезает ни за карточку, ни за свою ячейку:

- все 16 языков на самом узком экране (320 px), ширины 320–1280 px,
  плотность ×1–×3;
- крупный системный шрифт (Android: 130–200 %): если число или подпись не
  влезает в ячейку, карточка уменьшает их ровно настолько, чтобы влезло
  (`--hv-fit`, `--hv-fit-l`; пересчёт — при смене размера, когда догрузился
  свой шрифт, при смене языка и числа цифр в днях, не каждую секунду; в
  следующем кадре, а не прямо в ResizeObserver — без «ResizeObserver loop» в
  консоли); номер блока и награда переносятся после
  «/» и «→», а не за край;
- iPhone с вырезом и «полоской»: меню отступает от них снизу и сбоку
  (`env(safe-area-inset-*)`), в том числе справа на арабском;
- высокая контрастность Windows: полоса эпохи и рамки рисуются системными
  цветами, иначе полоса пропадала бы.

**Не засоряет сервер и телефон.** Сервер держит один ответ (заменяется
новым), время начала эпохи — одно на эпоху (раз в 4 года), не больше одного
фонового потока; файлов и базы нет. Журнал — не чаще строки в минуту и
только при сбое источников. Тест `test_memory_threads_and_cache_do_not_grow`
гоняет 20 000 ответов и 400 пересборок: память, потоки и кэш не растут. В
телефоне — одна запись `wt-halving-v1` (~300 байт, перезаписывается;
старше месяца или с прошедшим халвингом не используется, уборка хранилища
её знает), в памяти — форматы Intl на язык (не больше 16).

**Нагрузка.** В сеть сервер ходит, только когда кто-то открыл меню, и не
чаще раза в 5 минут: хеш последнего блока и сам блок — ~0,5 КБ вместо
30 КБ списка из 15 блоков (в 60 раз меньше); ответ-JSON читается не больше
4 КБ, одним разборщиком на всё время работы. Ответ человеку — ~190 байт,
~5 мкс на сервере. Приложение спрашивает раз в 5 минут, пока меню открыто
и приложение не свёрнуто, и перерисовывает карточку раз в секунду общим
таймером.

Отсчёт тикает на границе каждой секунды (`src/lib/tick.ts`), а не «раз в
1000 мс от запуска»: такие срабатывания на телефоне запаздывают по-разному, и
секунда в отсчёте иногда пропадала.

Безопасность: `/api/halving` открыт без Премиума, но идёт через nginx
(120 запросов в минуту на человека, `Cache-Control: no-store` — время
сервера в ответе всегда свежее) и не принимает от человека никаких
параметров. Адреса источников зашиты в коде, хеш блока перед подстановкой в
адрес проверяется, ответы ограничены по размеру. Источнику не верим на
слово: высота — не больше, чем при блоке раз в 5 минут с генезиса, время
блока — не из будущего и не старше суток, среднее — 480–720 с; то же
проверяет и приложение.

Защита от атак через взломанный или подменённый источник
(`tests/test_halving_security.py`, на настоящем HTTP-сервере):

| Атака | Что делает модуль |
|---|---|
| Увести сервер на внутренний адрес (SSRF: метаданные облака, localhost) или чужой сайт | ходит только по https и только на mempool.space, blockstream.info, blockchain.info; адрес с логином не годится; перенаправления (3xx) не выполняются |
| Подменить сертификат | сертификат и имя сервера проверяются |
| `1e400`, `Infinity`, `NaN` в числах | разбор отвергает — раньше `OverflowError` ронял сборку |
| JSON с вложенностью в сотни тысяч уровней | отвергается — раньше `RecursionError` |
| Число из миллиона цифр (CVE-2020-10735: секунды процессора) | целое длиннее 20 цифр не разбирается |
| Отдавать ответ по байту (держать поток часами) | срок на весь ответ, а не на каждый кусок |
| Ответ в гигабайт | читается кусками; больше заданного — отказ, а не обрезка (начало длинного ответа могло бы разобраться как правдоподобное) |
| Высота строкой, дробью, `true` | не принимается: высота и время блока — только целые числа |
| Ошибка, которой никто не ждал | сборка не падает: минута паузы, как при молчащих источниках, отдаётся последний хороший ответ |
| Подделать журнал (перевод строки, ANSI-коды в тексте ошибки) | в журнал — одна строка без управляющих символов, не длиннее 300 знаков |
| Лишние поля, `__proto__`, строки со скриптами в ответе | приложение отвергает ответ (`validHalving`) и хранит только известные поля (`pickHalving`); React не вставляет HTML |

| Подменить `HTTPS_PROXY` на сервере и пустить запросы через себя | прокси из окружения не берётся — только напрямую |
| «Zip-бомба»: 1 МБ сжатого, гигабайты после распаковки | просим ответ без сжатия, сами не распаковываем |
| Подсунуть человеку ссылку, скрипт или текст-инструкцию для ИИ | от источника наружу не уходит ни символа текста: в ответе только проверенные числа и наши строки |

**Защита от ИИ-агентов и от «тихих» правок.** ИИ-агент атакует теми же
путями, что человек, только быстрее и неутомимее: перебирает входы, шлёт
тысячи запросов, пробует подложить код. Поэтому защита построена так, чтобы
не зависеть от того, кто атакует:

- **Входа нет.** `/api/halving` не принимает параметров, ответ один на
  всех из кэша; сеть — не чаще раза в 5 минут при любом числе запросов,
  перебирать нечего.
- **Правила кода проверяются автоматически** (`tests/test_halving_policy.py`,
  по дереву разбора Python, а не поиском текста): только разрешённые
  импорты стандартной библиотеки, ни `eval`/`exec`/`open`, в сеть — одна
  дверь (`_fetch`, после проверки адреса), каждый адрес — https к одному из
  трёх источников; в приложении — ни вставки HTML, ни `eval`, ни сетевых
  запросов и хранилища из карточки, расчёт без импортов вообще, ответ в
  память и на устройство — только после проверки. Подложенный опасный код
  (руками или агентом) роняет тесты, и в main он не попадает.
- **Сборка на GitHub** — с наименьшими правами (только чтение), сторонние
  действия закреплены по хешу коммита (метку `v4` можно перевесить на
  подменённый код, хеш — нет), токен после checkout на диске не остаётся.
- **Сторонних пакетов у сервера модуля нет** — только стандартная
  библиотека Python: подменить в цепочке поставки нечего.

Фаззинг подмешивает эти тела в каждый источник и проверяет, что до общей
страховки в `build` дело не доходит ни разу.

Браузерный тест карточки — `npm run test:e2e` (`tests/e2e/halving.e2e.test.ts`,
один раз: `npm i` и `npx playwright install chromium`). Он поднимает
собранное приложение из `html/` (сначала `npm run build`), подменяет ответы
сервера, закрывает сеть наружу и закрепляет время в браузере, поэтому
отсчёт сверяется до секунды. Шрифт — настоящий IBM Plex Sans из `fonts/`:
с запасным строки переносились бы иначе, чем у людей. Проверяет: отсчёт, дату, эпоху, блок, награду;
часы телефона, сбитые на 3 часа; заглушку при медленном ответе; «нет
данных»; испорченный запас на устройстве; поломку внутри карточки
(предохранитель); экран 320 px с 544 и с 1 457 днями (ничто не шире своих
рамок); арабский (полоса растёт справа); доступность.

Ответ сервера описан одним образцом — `tests/fixtures/halving.json`: тест
сервера проверяет, что ответ совпадает с ним по полям и типам, тест
приложения — что приложение принимает его целиком. Поменяли формат с одной
стороны — тест упадёт, а не карточка у людей. Типы тестов проверяет
`npm run typecheck:tests`, серверный модуль и его тесты — анализатор ruff. `tools/guard.py`
запускает и его, а где Chromium нет — пишет, что пропустил.

На GitHub всё это идёт само на каждый push в main, pull request и по кнопке —
`.github/workflows/tests.yml`: `unit` (типы приложения и тестов, синтаксис
сервера, ruff, `npm test`) и
`e2e` (сборка и браузерный тест). Статус — на вкладке Actions репозитория.

Сборка на сервере укладывается в 20 секунд, даже если
источники зависли; пока идёт первый запрос, в меню — заглушка того же
размера.

Ответ проверяется целиком, включая необязательные поля: строка вместо
числа в `eta` раньше роняла отрисовку. Карточка обёрнута в `Boundary`
(`src/components/Boundary.tsx`): если она всё же упадёт, исчезнет только
она, а не всё приложение. Две недели после халвинга карточка пишет, что он
состоялся (сервер отдаёт `prev` — время блока прошлого халвинга).

## Правила, которые здесь соблюдаются

- **Дайджест вместо Cortex.** Сигналы и обучаемая модель убраны из обоих
  проектов: бот при запуске стирает их таблицы, в приложении на месте вкладки
  — «Дайджест». Выпуск собирает `digest_refresher` в 12:00 по Лондону (летом
  11:00 UTC, зимой 12:00 UTC — правило британского времени своё, без tzdata): самое
  крупное за сутки из каждой вкладки «Аналитики» (NetFlow, крупные ордера,
  ротация, лонг/шорт, позиции, фандинг) и разлоки на неделю вперёд по доле
  оборота. Выпуск пишется один раз и не пересчитывается, хранятся тридцать
  последних. Разделы про фьючерсы бесплатному не уходят с сервера — только
  отметка `{"locked": true}`, как и у самих вкладок.

- **Лайки и комментарии — под контролем сервера.** Комментарий до 500
  символов, без ссылок, не чаще раза в 20 секунд и не больше 30 в сутки;
  отказ приходит с причиной и кодом 200 — иначе приложение увидело бы только
  «нет ответа». Свой комментарий удаляет автор, любой — владелец бота (он же
  может закрыть автору комментарии). Таблицы дайджеста заводит бот, хозяин
  базы; `/forgetme` и «Удалить мои данные» стирают лайки, комментарии и
  запрет одинаковым списком в обоих местах.

Приложение не показывает того, чего не знает.

- **Нет котировок — нет графика.** Свечи берутся с четырёх бирж по очереди
  (Binance, Binance Vision, Bybit, KuCoin) через nginx. Не ответил никто —
  экран говорит об этом. Прошлая версия рисовала 32 точки линейной
  интерполяции между ценой входа и текущей: по виду график, по сути ничего.
- **Показатели за окно приходят с сервера.** Прошлая версия умножала
  прибыль на 1.85, 2.7 и 3.9, а доходность — на 0.72, 0.58 и 0.44 в
  зависимости от выбранного окна и за окнами никуда не ходила.
- **Каждая доска — свой рейтинг, а не срез одного.** Раньше у фьючерсов
  сотня кошельков отбиралась по прибыли, а винрейт, сделки и доходность
  сортировались внутри неё: «лучший винрейт» значило «лучший винрейт среди
  самых прибыльных». Теперь отбор идёт по всем, кто прошёл порог по числу
  закрытых сделок, и каждая доска берёт свою сотню по своему признаку. На
  базе в четверть миллиона филов это стоит секунду.
- **ROI по споту нет нигде.** Знаменатель собирается из цен DEX на момент
  покупки, часть монет куплена по ценам, которых уже не достать, а порог
  отсечения — десять долларов оборота. Доски нет ни в боте, ни в приложении,
  и самого числа в спотовых строках тоже нет: показатель, который никому не
  показывают, однажды покажут. Абсолютный PnL остаётся — он считается из тех
  же сделок, но ни на что не делится.
- **Доходность перпов считается от маржи, а не от депозита.** Размера
  депозита в `hl_fills` нет, поэтому знаменатель собирается по закрытиям:
  маржа сделки — это закрытый ею номинал, делённый на плечо, а закрытым
  считается не больше, чем стояло в позиции (у переворота половина объёма
  открывает новую). Тот же счёт, что в `hyperliquid_ui.cpp`.

  Раньше бралась наибольшая маржа среди филов серии, а маржа стоит в филе
  только когда бот успел снять состояние позиции: у кошелька, попавшего в
  наблюдение позже, открытий нет вовсе, и знаменатель выходил в разы меньше
  настоящего, потому что прибыль приходит с закрытий и считается целиком.
  Сверка по филам самой биржи: у `0x767a…0ace` доска показывала 1185% при
  настоящих 188%, у `0xcab5…6e6e` — 521% при 511%.

  Второй перекос был тоньше и стоил дороже: прибыль считалась по каждому
  закрытию, а маржа — только по строкам, где позиция обнулилась (`flat=1`)
  или случился переворот с ликвидацией (`dir_code >= 5`). Частичное закрытие
  у бота получает код 3 или 4 и флага `flat` не имеет, так что у всех, кто
  выходит из позиции частями, знаменатель считался по одному последнему
  куску: у `0x767a…0ace` выходило 31660% при настоящих 188%, у
  `0xcab5…6e6e` — 4092% при 511%. Поэтому условие «строка что-то закрыла»
  теперь одно на всех — `perp_close_sql()` в `whale_api.py` и обход позиции
  в `hyperliquid_ui.cpp`: числитель, знаменатель и счётчик сделок обязаны
  считать одни и те же строки. В боте по той же причине сделка засчитывается
  на каждом закрытии: раньше серия сливалась в счёт только по `flat`, и
  прибыль монеты, не успевшей закрыться внутри окна, пропадала совсем.
  Кошельки, у которых маржу посчитать не из чего, на доску ROI не попадают
  вовсе: ноль там читался бы как «торговал без прибыли». Порог — сто
  долларов маржи: на меньшей одна сделка даёт тысячи процентов. Прежняя
  формула `100·pnl / max(|pnl|·0.4, 1)` давала ровно ±250 почти всем, и
  какое-то время доска стояла пустой — это было честнее её.
- **На споте не лонгуют.** Позицию открывают в лонг или в шорт на перпах, а
  монету на споте покупают или продают — шортить её негде. Бот в чате так и
  писал, а приложение на обеих площадках ставило «Лонг / Шорт» и обещало
  сделку, которой не бывает. Сторона теперь выбирается одной функцией
  `sideKey(venue, long)` на карточке, в списке и в истории.

- **Поле графика всегда слева направо.** Направление письма страницы
  переворачивает раскладку и внутри svg: в арабском подписи цен уезжали за
  край, и от плашек оставался один знак доллара.

- **Ссылки на поток внизу карточки больше нет.** Число потока стоит в
  плитках там же, а отдельная строка «что покупают киты» вела на экран, с
  которого человек и пришёл.

- **Окон потока 1ч и 6ч больше нет.** Это про окно счёта потока китов, а не
  про горизонт прогноза. Модель обучена на суточном окне потока; на часовом у
  неё не было ни одного примера, и её оценка там была бы выдачей угадывания за
  счёт. Переключатель снят, сохранённый выбор убирает миграция третьей версии.

- **Вклад признака показывается с величиной, а не по месту в списке.** Бот
  пишет `flow:412` — имя и сдвиг вероятности в сотых долях процента. Рисовать
  длину полосы от порядкового номера значило бы выдумывать число, которого
  никто не считал.

- **Пятно импульса гаснет по часам svg, а не по часам стиля.** Прозрачность
  жила отдельной анимацией CSS с той же длительностью и задержкой, что и
  движение, — и этого мало: стилевые часы идут от разбора страницы, а часы
  svg от её загрузки, и расходятся ровно на это время. Пятно успевало
  проявиться раньше, чем трогалось с места, и его было видно светящейся
  точкой в углу картинки. Проверка ловила это одним провалом на пять
  прогонов; теперь обе анимации живут в svg и идут от одних часов.

- **Полоса готовности показывает 600, а не 400.** Обучение начинается с 400
  исходов, но приёмка требует ещё и скользящей проверки, а та считается
  только от 600: четыре раза учимся на прошлом и смотрим на следующем куске,
  и на меньшей выборке кусков просто не из чего нарезать. С порогом 400
  полоса наполнялась до края — «533 / 400», — и человек ждал неизвестно
  чего: модель в этот момент не могла быть принята ни при каком качестве.

- **Синхронизатор переводов падает на неразобранном ключе.** Его разбор
  `ru.cpp` запрещал фигурные скобки внутри значения, и ключ с подстановкой
  («угадывает {n} раз из 100») молча не попадал в словарь — на экране
  оставалось имя ключа. Теперь значение ищется как пара групп строковых
  литералов, а всё, что не разобралось, роняет скрипт с именем ключа.

- **Стоп и цели называет модель, а не множитель волатильности.** К лесу
  направления добавились два леса величины: как далеко цена уходит вверх и
  вниз за горизонт. Разметка берётся из истории цен — максимум и минимум хода от
  входа, — поэтому она считается и для трёх месяцев уже собранного журнала, а
  не только для будущих событий. Та же машина деревьев, другая функция потерь:
  квадратичная вместо логистической.

  Стоп ставится чуть дальше ожидаемого отката, иначе его снимает первым же
  шумом; цель чуть ближе ожидаемого хода, иначе до неё не доходят. Эти две
  поправки — про исполнение, а не про рынок, и других констант там нет.

  Уровни принимаются отдельно от направления и по своему признаку: средняя
  ошибка должна быть меньше, чем у предсказания «всегда средний ход». Не
  прошли — стоп с целью считает прежняя формула, и на экране состояния так и
  написано.

- **Ноль сделок — нет полосы.** Не деление на ноль и не `NaN%`.
- **Число алертов — из `me.alerts30d`.** Не вшитое `194` для всех.

Русский текст, который сервер собирает сам («покупка», «лонг 5×», «5 мин»),
разбирается в `lib/labels.ts` и `lib/relative.ts` и показывается на языке
интерфейса.

## Развёртывание

Контейнер — nginx со статикой; API живёт отдельно и подключается через
`API_UPSTREAM`.

| Переменная | Что делает |
|---|---|
| `PORT` | порт nginx, по умолчанию 8080 |
| `API_UPSTREAM` | адрес whale_api; без него прокси идёт в `127.0.0.1:8090` |
| `API_KEY` | общий секрет с API; пусто — порт API открыт всем |

У `whale_api.py` свои переменные — см. `whale-api.service`. Обязательны
`WHALE_TG_TOKEN` (без него служба не поднимется: проверять подпись нечем),
`WHALE_API_ORIGIN` (адрес мини-аппа, иначе браузер получит отказ по CORS) и
`WHALE_API_KEY` — тот же, что `API_KEY` у контейнера.

Сейчас nginx и API — на одной машине, и `WHALE_API_HOST=127.0.0.1`: порт
8090 снаружи недоступен. Если nginx окажется на другой машине (как раньше в
Cloud Run), между ними будет интернет: тогда `WHALE_API_HOST=0.0.0.0`, а порт
закрывают `WHALE_API_KEY` и firewall, открытый только адресам той машины.

**`API_UPSTREAM` задавай по HTTPS.** По HTTP через интернет уедут открытым
текстом и `X-Telegram-Init-Data`, и `X-Api-Key`.

### График (`src/chart/`)

Свой график вместо виджета TradingView, на canvas, без библиотек:

- `data.ts` — свечи: Binance (`/klines-vision`, `/klines`), Hyperliquid
  (`/klines-hl`, в том числе рынки HIP-3 вроде `xyz:NVDA`), Bybit spot и
  perp, KuCoin. Первый ответивший источник запоминается; история листается
  назад страницами по 1000 свечей; живая свеча — вебсокетом биржи прямо из
  браузера, не открылся — опрос раз в 10 с. Таймфрейма нет у биржи — он
  собирается из меньшего.
- `engine.ts` — движок: свечи, полые, Хейкен-Аши, бары, линия, область;
  панели осцилляторов; авто, ручная и лог-шкала; перекрестие; отсчёт до
  закрытия свечи; щипок, инерция, долгое нажатие.
- `indicators.ts` — индикаторы (MA, EMA, WMA, HMA, VWMA, DEMA, TEMA, лента
  EMA, Боллинджер, Кельтнер, конверт, Дончиан, VWAP, SuperTrend, Parabolic
  SAR, Ишимоку, RSI, MACD, Stoch, Stoch RSI, CVD, ATR, OBV, MFI, CCI,
  ADX/DMI, Williams %R, Momentum, ROC, Aroon, CMF, AO, TRIX, UO, Squeeze
  Momentum, A/D, Choppiness, HV, Vortex, Fisher, BBW, %B, BBP, EFI, объём) и
  три своих: открытый интерес по 32 биржам, средний фандинг и уровни
  ликвидаций — из API.
- `draw.ts` — 21 инструмент рисования: линии, каналы, весь набор Фибоначчи
  (коррекция с уровнями на выбор и подсвеченным «золотым карманом»
  0.618–0.65, расширение, веер, временные зоны), волны Эллиотта (импульс
  1–5 с проверкой трёх правил и пропорциями волн, ABC, ABCDE, WXY), позиции,
  линейка, текст, кисть. Точки хранятся во времени и цене, поэтому рисунок не
  съезжает при смене таймфрейма. Отмена и возврат, лупа под пальцем.
- Индикаторов 53 + 3 своих, в том числе автоанализ: профиль объёма, авто-
  уровни поддержки и сопротивления, автофибо, ZigZag, пивоты, дивергенции
  RSI, свечные паттерны, канал регрессии. Далёкие уровни не растягивают шкалу
  цены — у края экрана для них ярлык со стрелкой.
- Свои данные на свечах: ликвидации с 11 бирж (`/api/chart/liqs` — по
  свечам нужного размера из `liq_ev`) и сделки китов базы на Hyperliquid от
  $100 000 за неделю (`/api/chart/whales` — один проход по `hl_fills` раз в
  5 минут на все монеты).
- Алерты по цене: горизонталь → «🔔 Алерт». Алерт хранится в `px_alerts`
  (не больше 30 на человека), `pxa_loop` раз в 10 с берёт цены одним запросом
  (Binance spot через data-api, остальное — Hyperliquid allMids, в том числе
  HIP-3) и пишет ботом на языке человека; сработавший снимается и неделю
  виден в списке. Линию подвинули — алерт переезжает, удалили — снимается.
- Алерты и на наклонных линиях (тренд, луч, продлённая): сервер хранит две
  точки линии и считает её уровень на текущий момент — на лог-шкале в
  логарифмах, как линия и нарисована. У позиции лонг/шорт — два алерта:
  тейк и стоп.
- Рисунки (по монете) и настройки графика хранятся и на сервере
  (`chart_draw`, `chart_prefs`): у каждой записи время, новее — побеждает,
  поэтому график один на телефоне и на компьютере.
- Сравнение: до трёх монет на одном графике в процентах от общей точки
  старта (первой видимой свечи); шкала в % — и вручную кнопкой «%».
- Снимок графика 📷: движок перерисовывает график в 1280×800 (больше
  истории, чем на экране телефона), сверху монета и цены, снизу
  @WalletTrackerAppBot; бот присылает картинку в чат (`/api/chart/snap`,
  своя широкая норма тела в nginx, не больше 20 в час).
- ⛶ — во весь экран (в Telegram 8.0+ ещё и полноэкранный режим самого
  мини-приложения). Клавиши для Telegram на компьютере: Alt+H/J/T/F/V/R/P/M —
  инструменты, Ctrl+Z / Ctrl+Y, Delete, Esc, ← →, + −.
- Технический рейтинг по 26 индикаторам (как Technical Ratings у
  TradingView) — плашкой на графике и разбором словами.

nginx держит последнюю страницу свечей 4 секунды в своём кэше (`klines`):
тысяча человек на BTC/1H — один запрос к бирже.

### Щит API (`wt_shield.py`)

Стоит перед каждым обработчиком; только стандартная библиотека.

| От чего | Как |
|---|---|
| Тело в гигабайт (забить память) | длина проверяется до чтения: больше 16 КБ — 413 |
| Медленный клиент (Slowloris) | тайм-аут сокета 20 с; в nginx — 10 с на заголовки и тело |
| Тысяча соединений разом | не больше 256 одновременно, сверх — 503 без отдельного потока |
| Подбор `X-Api-Key` мимо nginx | 20 промахов за 10 минут — бан адреса на час |
| Выход из папки, нулевой байт | путь с `..`, `%00`, `\` или управляющими символами — 400 |
| Утечка подписи Telegram | подпись берётся только из заголовка, не из адреса; в журнале — `init=***` |
| Утечка устройства сервера | при сбое наружу уходит номер ошибки, текст — только в журнал |
| Подмена X-Forwarded-For | без ключа API ему не верит вовсе; с ключом берётся адрес, дописанный Google, — левее стоящее клиент мог подделать |
| Общий адрес на всех (Cloud Run) | адрес человека — из X-Forwarded-For, а не узел Google: иначе «3 пробы с адреса в сутки» и лимиты nginx делились бы на всех |
| Чужой сайт встраивает ответ | `nosniff`, `default-src 'none'`, `frame-ancestors 'none'`, `DENY` |
| Перехват по дороге | `WHALE_API_TLS_CERT` и `WHALE_API_TLS_KEY` — API сам говорит по TLS |
| Усиление через логотипы | проверка неизвестного логотипа — не больше восьми одновременно |

nginx держит к API постоянные соединения (`upstream whale_api`, по 16 на
процесс): без них каждый запрос — новое рукопожатие через интернет. Замер
на 4 ядрах: 4 500 запросов в секунду с постоянными соединениями против
1 900 с новым на каждый (простой ответ; тяжёлые — медленнее).

Переменные: `WHALE_API_MAX_BODY`, `WHALE_API_MAX_CONN`, `WHALE_API_CONN_TIMEOUT`,
`WHALE_API_TLS_CERT`, `WHALE_API_TLS_KEY`.

TLS без домена — самоподписанным сертификатом:

```
openssl req -x509 -newkey rsa:2048 -nodes -days 3650 -subj "/CN=whale-api" \
  -keyout /etc/whale-api/key.pem -out /etc/whale-api/cert.pem
```

и в `/etc/whale-api.env`: `WHALE_API_TLS_CERT=/etc/whale-api/cert.pem`,
`WHALE_API_TLS_KEY=/etc/whale-api/key.pem`; у Cloud Run `API_UPSTREAM` —
`https://…:8090`. Шифрует он так же, как купленный.

### Свой сервер (VPS) — сейчас так: https://wallettracker.pl

Всё на одной машине: бот, `whale_api` и nginx со страницами. nginx берёт
конфиг из того же `nginx.conf`, отличия делает `tools/vps_nginx.py`: https
на 443 (сертификат Let's Encrypt), 80 — только перенаправление, адрес
человека — `$remote_addr` (на своём сервере `X-Forwarded-For` пишет сам
человек — брать адрес оттуда нельзя), кэш — в `/var/cache/nginx`, страницы
— прямо из `html/` репозитория (`git pull` обновляет и их).

```
sudo apt -y install git g++ libboost-dev libcurl4-openssl-dev libsqlite3-dev sqlite3 \
  python3 python3-pil nginx certbot ufw
sudo certbot certonly --standalone -d wallet.example.com \
  --pre-hook "systemctl stop nginx" --post-hook "systemctl start nginx"
sudo mkdir -p /var/cache/nginx   # в Debian 13 этой папки нет, а кэш nginx создаёт только последний уровень
sudo python3 tools/vps_nginx.py wallet.example.com | sudo tee /etc/nginx/sites-available/wallettracker
```

У службы API на такой машине `WHALE_API_HOST=127.0.0.1` (nginx рядом) и
`WHALE_API_ORIGIN=https://wallet.example.com`; у бота
`WHALE_MINIAPP_URL` — тот же адрес.

#### Автовыкат

Как раньше Cloud Run выкатывал каждый push, так здесь раз в минуту
`tools/autodeploy.sh` смотрит в GitHub и выкатывает новые коммиты обоих
репозиториев:

- страницы (`html/`) — сразу, nginx отдаёт их из папки;
- сервер (`*.py`) — проверка синтаксиса и перезапуск `whale-api`;
- `nginx.conf`, `tools/vps_nginx.py` — новый конфиг nginx, `nginx -t`, reload;
- бот (`*.cpp`, `*.h`, `build.sh`) — сборка в `whale_bot.new`, подмена и
  перезапуск `whalescanner`.

Сломанное откатывается само: ошибка синтаксиса, бот не собрался, служба не
поднялась — прежний коммит и прежняя версия службы. Такой коммит больше не
выкатывается; следующий — как обычно. Git и сборка идут от владельца папок,
не от root.

Установщик заодно ограничивает журнал системы 14 днями
(`/etc/systemd/journald.conf.d/wt-retention.conf`): в нём бывают IP-адреса и
Telegram ID, а политика конфиденциальности обещает этот срок (RODO).

```
sudo tools/autodeploy-install.sh wallet.example.com   # включить (и после правок autodeploy.sh или установщика)
journalctl -u wt-autodeploy -f                         # что выкатилось
sudo systemctl disable --now wt-autodeploy.timer       # выключить
```

### Автопостинг дайджеста в канал

Сразу после выхода выпуска (12:00 по Лондону) бот публикует его альбомом из
пяти картинок с подписью в `WHALE_DIGEST_CHANNEL` (по умолчанию

Картинку рисует `wt_digest_img.py` — нужен Pillow: `sudo apt install -y python3-pil`.
Без него выпуск уходит в канал текстом. Что опубликовано — таблица
`digest_channel`; не ушло — повтор через 10 минут, до шести попыток.
