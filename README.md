# Wallet Tracker — мини-апп

Telegram-мини-апп поверх бота **WhaleScanner**. Задача — перенести бота в
экран: те же разделы, те же слова, но с графиками, логотипами монет и без
пролистывания чата.

Словари не переводились заново: они собираются прямо из исходников бота,
поэтому человек, пришедший из чата, встречает знакомые формулировки на
всех шестнадцати языках.

## Что внутри

```
src/i18n/       16 языков × 373 ключа, собираются tools/sync-i18n.py
src/lib/        запросы, форматирование, свечи, разбор серверных подписей
src/store/      состояние: сохраняемое (app) и живое (live)
src/components/ строка, плитки, кнопка, логотип монеты, графики, тосты
src/screens/    вкладки и экраны стека
src/styles/     тема, сброс, правила приложения
tools/          сборка словарей из бота
whale_api.py    JSON API поверх whale_bot.db и hyperliquid.db
nginx.conf      статика, прокси к API и к биржам, кэш логотипов
fetch_logos.py  разовая выкачка логотипов в html/coins/
```

## Разделы — как в боте

| Бот | Мини-апп |
|---|---|
| 👤 Мой аккаунт | вкладка «Мои кошельки»: пульс за сутки, кошельки, порог, алерты |
| 🏆 Топ трейдеров | вкладка «Топ»: площадка, вид рейтинга, окно 30/90/180/365 |
| 📊 Аналитика | вкладка «Аналитика»: поток, крупнейшие сделки, ликвидации, фандинг, ротация |
| 📡 Cortex | вкладка «Cortex»: сигналы, история, состояние модели |
| 💰 Порог алертов | экран порога: пресеты бота и своя сумма |
| ⭐ Премиум | экран премиума и переход в чат за оплатой |
| 🌐 Языки | экран языка, выбор пишется в ту же строку `users` |
| ❓ Помощь | экран помощи |
| 📈 Открытые позиции | экран позиций и карточка каждой |

Подписку покупают и здесь, и в чате: звёздами Telegram или в USD₮ сети TON.
Подробности — в разделе «Оплата премиума».

## Как запустить

### Локально, посмотреть глазами

```bash
npm install
npm run dev            # http://localhost:5173
```

Dev-сервер отдаёт только статику, поэтому `/api`, свечи и логотипы он
проксирует на уже выкаченный адрес — ни nginx, ни баз бота поднимать не
нужно. Свой адрес: `WT_PROXY=https://… npm run dev`.

Подписи Telegram в обычном браузере нет, поэтому приложение переходит на
публичный `/api/market`: рынок, топ трейдеров, сигналы и графики видны,
свои кошельки и порог — нет. Чтобы увидеть личные данные, открой мини-апп
из чата с ботом.

### Собрать

```bash
npm run typecheck
npm run build          # результат в html/
```

`build` идёт строго по порядку: проверка типов → очистка → сборка. Очистка
стоит после `tsc` намеренно: иначе ошибка типов оставляла бы `html/` пустым —
файлы прошлой сборки уже удалены, новые ещё не собраны. Без этого файлы прошлых сборок копились бы: имена содержат хеш,
поэтому новая сборка не перезаписывает старую, а ложится рядом. `html/coins`
очистка не трогает — там 1547 логотипов, которые сборка не создаёт.

Отдельно очистку можно позвать как `npm run clean`.

Номер сборки берётся из `BUILD_NUMBER`, иначе подставляется дата.

`emptyOutDir` выключен намеренно: в `html/` лежит `coins/` — 1547 логотипов
на 26 МБ, сборка их не трогает.

Имена файлов содержат хеш. Это не украшение: nginx отдаёт `/assets/` как
неизменяемые на год, и прежняя сборка без хешей приводила к тому, что после
выката браузер брал новый `app.js` вместе с прошлогодним `routes.js` и падал
с «Unexpected end of input».

### Словари

```bash
python3 tools/sync-i18n.py ../WhaleScanner
```

Собирает `src/i18n/*.ts` из `ru.cpp` (en + ru) и `translations.cpp`
(остальные 14). Ключи оболочки мини-аппа лежат в `tools/i18n-extra.json`;
скрипт падает, если для ключа не заполнен хоть один язык.

Словари объявлены как `Record<DictKey, string>`, а не `Partial`: пропустишь
ключ — сборка встанет и назовёт его. В прошлой версии они были `Partial`,
недостающее молча подменялось английским, и арабский жил с 29 ключами из 427.

### Логотипы

```bash
python3 fetch_logos.py
```

Кладёт `coins/bsc/<checksum>.png` и `coins/hl/<имя>.svg`, пишет
`coins_manifest.json`. Папка едет в репозиторий как `html/coins/`, манифест
остаётся рядом с `whale_api.py`: по нему API понимает, какие файлы есть, и
не предлагает браузеру ходить наружу. Перезапустив выкачку, обнови и то, и
другое — иначе API начнёт указывать на несуществующие файлы.

```bash
python3 tools/sync-coin-logos.py
```

Собирает `src/components/coin-logos.ts` — тикер → адрес логотипа на
CoinGecko, через наш же `/cglogo/`. Нужен монетам, которых нет ни в образе,
ни у Hyperliquid: на BingX и Gate торгуется впятеро больше тикеров, и без
этого списка половина строк фандинга — буквы в кружках. Выверенные вручную
адреса лежат в `coin-fallback.ts` и главнее собранных.

Цепочка перебора в `CoinIcon` идёт от точного к общему: файл из образа →
рисунок площадки → монета по тикеру → биржевой логотип. Рынки HIP-3
(`xyz:NVDA`, `para:TTWO`, `mkts:GOLD`) Hyperliquid раздаёт по точному имени,
и приставка у него строчная: `XYZ:SMSN.svg` отдаёт не картинку, а страницу
приложения — с кодом 200, так что на ошибку это даже не похоже. Если своя
площадка рисунка не выложила, берётся рисунок `xyz` — самой большой из них.

Акции последним звеном идут через `/stlogo/` (`assets.parqet.com`): их на
биржах уже десятки — у Hyperliquid как рынки HIP-3, у остальных обычными
тикерами (AMZN, TSLA, QQQ, MCD). До этого звена доходят только строки, у
которых не нашлось ни файла, ни рисунка площадки, ни монеты с таким
тикером. Плата — редкая ошибка: у монеты с коротким именем, похожим на
биржевой код, окажется логотип компании. Известные совпадения разобраны
вручную в `coin-fallback.ts`: HEI — это Heima, а не HEICO, BTR — Bitlayer,
WEN — мемкоин; у природного газа (NG) логотипа нет ни у кого, и там честнее
оставить букву, чем показать золотодобытчика с тем же кодом.

На живой выгрузке из 231 инструмента логотип находится у 204; было 120.

### Оплата премиума

Подписку покупают прямо в приложении: звёздами Telegram и в USD₮ сети TON.
Оплаты монетой TON (она же GRAM по курсу) больше нет нигде — ни в чате, ни в
приложении: цена в долларах равна цене в USD₮, и курс, которого могло не
быть, из расчёта ушёл вместе с ней.
Своей выдачи подписки в API нет намеренно — она уже написана в `premium.cpp`
бота и должна остаться в одном месте: там продление срока, запись платежа в
историю и уведомление в чат.

Звёзды. Счёт создаёт API (`createInvoiceLink` с той же нагрузкой и суммой,
что выставляет бот), окно оплаты открывает Telegram, подтверждение платежа
приходит боту в `getUpdates` — и подписку выдаёт он, как при покупке из чата.

USD₮. Счёт кладётся в таблицу `ton_invoices` бота с пометкой `kind='usdt'`,
человек переводит деньги на тот же кошелёк, что и в чате, с памяткой в
комментарии. Адрес берётся так же, как в `tonWallet()` из `premium.cpp`:
переменная `TON_WALLET_ADDRESS`, а без неё — тот же адрес по умолчанию. У
бота и у API разные службы, и требовать переменную только здесь значило бы
оставить приложение без кнопки оплаты на ровном месте. Дальше а приход видит опрос бота `pollUsdtPayments` — он сверяет
мастер-контракт USD₮, занимает счёт одним обновлением и выдаёт подписку.
Перевод из приложения подписывает кошелёк через TON Connect; рядом с кнопкой
показаны адрес, сумма и памятка — кошельком, который TON Connect не знает,
платят руками.

Тело перевода жетона собирается в `src/lib/ton.ts` без библиотек: нужна одна
ячейка без ссылок, а `@ton/core` весит сотни килобайт. Сборка сверена с ним
байт в байт — `node tools/ton-boc-check.mjs`, он же стоит только для этой
проверки и в сборку приложения не входит.

Пока бот не перезапущен с поддержкой USD₮, приложение кнопку не показывает:
признак — столбец `kind` в его таблице счетов. Иначе счёт выставился бы,
деньги ушли, а выдать подписку было бы некому.

### Фандинг

Ставки берутся с двенадцати площадок: Hyperliquid — из своей базы (её
наполняет бот), остальные — запросами наружу, своим потоком раз в десять
минут. Поэтому машине с API нужен исход на `fapi.binance.com`,
`api.bybit.com`, `www.okx.com`, `api.bitget.com`, `open-api.bingx.com`,
`api.gateio.ws`, `api.mexc.com`, `api-futures.kucoin.com`,
`futures.kraken.com`, `api.international.coinbase.com`, `fapi.asterdex.com`,
`api.coingecko.com` и `toncenter.com` (жетонный кошелёк плательщика).

Домен фьючерсов MEXC (`contract.mexc.com`) отказывает облачным адресам, тот
же API отдаёт `api.mexc.com` — по нему и ходим. Размер контракта нужен там,
чтобы перевести открытый интерес в доллары; выгрузка на два мегабайта
держится шесть часов, а не тянется каждый круг.

Binance и Bybit отказывают облачным адресам (`451` и `403`) — и с нашей
машины их собственный API недоступен. Для них есть запасной источник:
доска деривативов CoinGecko, те же пары со ставкой, открытым интересом и
оборотом. Чего там нет — шага выплат и времени следующей: у обеих бирж по
умолчанию восемь часов, отсчёт идёт до ближайшей границы 00/08/16 UTC, и
для пар с другим шагом время приблизительное. Точные значения приходят
только там, где доступен API самой биржи. Площадка, которая не ответила и
не имеет запасного источника, просто не появляется в приложении.

Перекосы отдаются все: в общей выгрузке лежит первая страница каждой доски,
остальные достаются `/api/fund?ex=&offset=&limit=` из тех же готовых досок,
что обновляет фоновый поток. Ставки приводятся к суточным — только ими
биржи и сравнимы: Hyperliquid, Kraken, Coinbase и Aster платят каждый час,
OKX, Gate, Bitget, MEXC и KuCoin — раз в час, четыре или восемь, у каждой
пары свой шаг, и он приходит в ответе; остальные раз в восемь.

Площадки выбираются лентой, а не сеткой плиток: двенадцать плиток занимали
пол-экрана, и список строк, ради которого раздел и открывают, уезжал вниз.
В ленте выбранная площадка стоит в середине и в полный размер, соседние
мельче, а выбор идёт за прокруткой — но не на каждый пиксель, а когда лента
остановилась: иначе, пока палец ведёт от Binance к Bybit, приложение успело
бы сходить за двумя лишними досками.

Лента кольцевая: список повторён копиями, и когда прокрутка уходит из
средней, положение молча переносится в неё же — карточки в копиях
одинаковые, подмены не видно, а края, в который лента упиралась, больше
нет. Копий тем больше, чем короче список: одного сильного маха должно не
хватать, чтобы долететь до конца. Подсвечена ровно одна карточка — та, что
в середине: на коротком списке две копии одной площадки попадают на экран
разом, и подсветка по названию зажигала бы заодно и боковую.

### Бесплатная неделя и удаление данных

Неделя премиума выдаётся один раз на аккаунт — по строке в `trial_granted`.
Эта строка единственная, что переживает «удалить мои данные»: и `forgetUser()`
бота, и `mutate('forget')` здесь стирают всё остальное, но не её. Пока она
удалялась вместе с профилем, цикл «удалил данные → /start → снова семь дней»
работал без конца. В строке нет ничего, кроме chat_id и даты выдачи, и об
этом сказано и в политике конфиденциальности, и в предупреждении перед
удалением.

Новый аккаунт Telegram — это новый chat_id, и неделю он получит. Без
привязки к телефону или к платежу это не лечится ничем, что у нас есть.

## Правила, которые здесь соблюдаются

Приложение не показывает того, чего не знает.

- **Нет котировок — нет графика.** Свечи берутся с четырёх бирж по очереди
  (Binance, Binance Vision, Bybit, KuCoin) через nginx. Не ответил никто —
  экран говорит об этом. Прошлая версия рисовала 32 точки линейной
  интерполяции между ценой входа и текущей: по виду график, по сути ничего.
- **Показатели за окно приходят с сервера.** Прошлая версия умножала
  прибыль на 1.85, 2.7 и 3.9, а доходность — на 0.72, 0.58 и 0.44 в
  зависимости от выбранного окна и за окнами никуда не ходила.
- **Каждая доска — свой рейтинг, а не срез одного.** Раньше у фьючерсов
  сотня кошельков отбиралась по прибыли, а винрейт, сделки и доходность
  сортировались внутри неё: «лучший винрейт» значило «лучший винрейт среди
  самых прибыльных». Теперь отбор идёт по всем, кто прошёл порог по числу
  закрытых сделок, и каждая доска берёт свою сотню по своему признаку. На
  базе в четверть миллиона филов это стоит секунду.
- **ROI по споту нет нигде.** Знаменатель собирается из цен DEX на момент
  покупки, часть монет куплена по ценам, которых уже не достать, а порог
  отсечения — десять долларов оборота. Доски нет ни в боте, ни в приложении,
  и самого числа в спотовых строках тоже нет: показатель, который никому не
  показывают, однажды покажут. Абсолютный PnL остаётся — он считается из тех
  же сделок, но ни на что не делится.
- **Доходность перпов считается от маржи, а не от депозита.** Размера
  депозита в `hl_fills` нет, поэтому знаменатель собирается по закрытиям:
  маржа сделки — это закрытый ею номинал, делённый на плечо, а закрытым
  считается не больше, чем стояло в позиции (у переворота половина объёма
  открывает новую). Тот же счёт, что в `hyperliquid_ui.cpp`.

  Раньше бралась наибольшая маржа среди филов серии, а маржа стоит в филе
  только когда бот успел снять состояние позиции: у кошелька, попавшего в
  наблюдение позже, открытий нет вовсе, и знаменатель выходил в разы меньше
  настоящего, потому что прибыль приходит с закрытий и считается целиком.
  Сверка по филам самой биржи: у `0x767a…0ace` доска показывала 1185% при
  настоящих 188%, у `0xcab5…6e6e` — 521% при 511%.

  Второй перекос был тоньше и стоил дороже: прибыль считалась по каждому
  закрытию, а маржа — только по строкам, где позиция обнулилась (`flat=1`)
  или случился переворот с ликвидацией (`dir_code >= 5`). Частичное закрытие
  у бота получает код 3 или 4 и флага `flat` не имеет, так что у всех, кто
  выходит из позиции частями, знаменатель считался по одному последнему
  куску: у `0x767a…0ace` выходило 31660% при настоящих 188%, у
  `0xcab5…6e6e` — 4092% при 511%. Поэтому условие «строка что-то закрыла»
  теперь одно на всех — `perp_close_sql()` в `whale_api.py` и обход позиции
  в `hyperliquid_ui.cpp`: числитель, знаменатель и счётчик сделок обязаны
  считать одни и те же строки. В боте по той же причине сделка засчитывается
  на каждом закрытии: раньше серия сливалась в счёт только по `flat`, и
  прибыль монеты, не успевшей закрыться внутри окна, пропадала совсем.
  Кошельки, у которых маржу посчитать не из чего, на доску ROI не попадают
  вовсе: ноль там читался бы как «торговал без прибыли». Порог — сто
  долларов маржи: на меньшей одна сделка даёт тысячи процентов. Прежняя
  формула `100·pnl / max(|pnl|·0.4, 1)` давала ровно ±250 почти всем, и
  какое-то время доска стояла пустой — это было честнее её.
- **Скоринг Cortex — градиентный бустинг, а не линия.** Модель живёт в
  `oracle.cpp` бота, признаков 35 вместо одиннадцати, и берутся они не только
  из потока китов: доходности за час, шесть и сутки, реальная волатильность и
  её всплеск, ATR, место цены в недельном коридоре, RSI, тренд к средней,
  фандинг и его отклонение от недельного, изменение открытого интереса за час
  и за сутки, отношение интереса к обороту, перекос ликвидаций, плечо,
  ликвидность пула, режим биткоина, ширина рынка и час суток. Линия не умеет
  сказать «приток помогает, но только при низкой волатильности», дерево умеет —
  на подставном мире с ровно таким правилом лес даёт AUC 0.90, а логистическая
  регрессия 0.52.

  Чего в базе нет, берётся у биржи: часовые свечи Hyperliquid
  (`hl_candles`) дают настоящие максимум, минимум и объём за час, а заодно
  историю на три месяца назад — новые признаки работают на всём журнале, а не
  только на будущих событиях. По сотне монет круг занимает около часа,
  восемь запросов за заход: тик оракула живёт в общем потоке обслуживания
  базы, и занимать его на минуты нельзя.

- **Признаки считаются одной функцией и только по прошлому.** `featuresOf` в
  `oracle.cpp` зовётся и при обучении на журнале (время — момент события), и
  при живом счёте (время — сейчас). Разойдись эти два пути, модель в бою вела
  бы себя не так, как на проверке, и заметить это было бы нельзя. Всё, что
  позже указанного часа, для признаков не существует: ряд ищется двоичным
  поиском по времени, и проверка на подставных данных сверяет, что дописанное
  будущее не меняет ни одного из 35 чисел.

- **Модель принимается, только если она лучше постоянного прогноза.** Выборка
  делится по времени на три части: обучение, проверка (ранняя остановка и
  калибровка Платта) и тест, которого модель не видела вовсе. Нужны сразу три
  условия: AUC на тесте от 0.55, потери ниже потерь постоянного прогноза и
  средний AUC скользящей проверки от 0.52. Не прошла — остаётся прежняя
  линейная модель, нет и её — формула. На подставном мире без всякого
  правила модель именно так и отвергается; это проверяется тестом наравне с
  успехом, потому что «модель», под которой монетка, хуже честной формулы.

  На экране состояния поэтому не одна «точность»: при 54% роста в выборке
  прогноз «всегда вверх» даёт те же 54%. Рядом всегда стоят AUC, потери и
  потери базы, размер теста и скользящая проверка.

- **Фильтр в 2% смещает выборку.** Событие, где цена за сутки прошла меньше
  двух процентов, в обучение не идёт — так было и у линейной модели, и счётчик
  «готовых результатов» на экране считает так же. Но у этого есть цена: на
  спокойном рынке движения мельче, и такие события выбрасываются чаще, чем на
  разогнанном. Замечено на подставных данных: правило силой в 2% после фильтра
  становится невидимым, силой в 6% — видимым. Порог общий с `ai.cpp`
  (`ORACLE_MIN_MOVE` и `AI_MIN_TRAIN`), менять его нужно в обоих местах сразу.

- **Сигналы считает бот, API их только отдаёт.** Раньше whale_api.py считал
  их второй раз своей формулой: уверенность выходила как «50 + модуль потока
  × 8», причины были вшитым списком правил, а обученная модель жила в боте и
  до приложения не доходила вовсе — на экране стояло 99%, которых никто не
  считал. Теперь бот раз в пять минут пишет готовые строки в `ai_signals`
  (сторона, вероятность модели, уровни, причины), а `_signals()` их читает.
  Повторять тридцать пять признаков и лес деревьев на втором языке нельзя:
  две реализации разойдутся, и заметить это будет не по чему.

- **Причина сигнала — вклад признака, а не правило.** Признак подменяется
  срединным значением обучающей выборки, и разница показывает, на сколько он
  сдвинул именно эту оценку. Знак — в сторону сигнала: «+» довод за, «−»
  против. Доводы «против» показываются тоже: прятать их значило бы рисовать
  модель увереннее, чем она есть. Середины едут вместе с лесом в том же блобе
  (формат ORC2) — по нулям считать нельзя, у объёма и числа кошельков ноль
  означает «сделок не было», а не «обычный день».

- **Окон потока 1ч и 6ч больше нет.** Модель обучена на суточном окне и
  суточном горизонте; на часовом окне у неё не было ни одного примера, и её
  оценка там была бы выдачей угадывания за счёт. Переключатель снят,
  сохранённый выбор убирает миграция третьей версии.

- **Графика оракула — три элемента и ни одного лишнего.** Шкала значения
  против предела (`Meter`), полосы в обе стороны от нуля (`Diverging`) и
  обычные полосы (`Bars`). Круговых индикаторов и пирогов нет: одно значение
  — это шкала или число, а не диаграмма из одной доли.

  Отметка на шкале важнее заливки. «Вероятность 61%» само по себе не значит
  ничего, значит только расстояние от 50%, где монетка; у AUC — от 0.5. Без
  отметки шесть десятых читаются как «почти наверняка».

  Цвет никогда не единственный признак: у расходящихся полос сторона и знак
  в подписи говорят то же, что зелёный и красный. Зелёный с красным различим
  не для всех глаз — пара проверена валидатором палитры (разделение при
  дейтеранопии ΔE 8.9 при пороге 8), но полагаться на один цвет всё равно
  нельзя.

- **Вклад признака показывается с величиной, а не по месту в списке.** Бот
  пишет `flow:412` — имя и сдвиг вероятности в сотых долях процента. Рисовать
  длину полосы от порядкового номера значило бы выдумывать число, которого
  никто не считал.

- **История сигналов — про выданные сигналы.** Раньше экран считал строки
  журнала обучения (`ai_events`): монеты, которые сигналами никогда не были,
  последние сорок подряд. «По цели» и «по стопу» брались от выдуманных
  порогов 3.75% и −2.5%, не связанных ни с одним настоящим уровнем, а
  «угадано» означало «поток угадал направление». Теперь бот ведёт
  `ai_signal_log`, и закрывается сигнал обходом часов: что случилось раньше
  — цель или стоп. У перпов есть максимум и минимум часа из свечей, у спота
  только закрытие часа — касание внутри часа там не видно. Задеты оба уровня
  в одном часе — считается стоп.

  Доля попаданий считается от решённых, а не от всех: сигнал, который за
  сутки не дошёл ни до цели, ни до стопа, не был ни угадан, ни нет.

- **Пустой список и непринятая модель объясняют себя.** Пустых состояний
  два: бот ни разу не присылал сигналов (таблицы нет — значит его не
  перезапускали) и бот посчитал, но ничего не прошло отбор. Модель без
  приёмки тоже показывает причину: `ai_model_try` хранит последнюю попытку,
  и на экране видно, насколько AUC не дотянул до порога.

- **На главном экране Cortex нет ни одного технического числа.** AUC,
  логарифмические потери и скользящая проверка живут на экране состояния, и
  там под каждым стоит строчка, что оно значит. На вкладке — предложения:
  «Модель работает · угадывает 61 раз из 100», «пока не лучше монетки»,
  «11 из 19 сигналов дошли до цели». Человек, открывший вкладку впервые,
  должен понять, что это, не зная, что такое AUC.

- **Синхронизатор переводов падает на неразобранном ключе.** Его разбор
  `ru.cpp` запрещал фигурные скобки внутри значения, и ключ с подстановкой
  («угадывает {n} раз из 100») молча не попадал в словарь — на экране
  оставалось имя ключа. Теперь значение ищется как пара групп строковых
  литералов, а всё, что не разобралось, роняет скрипт с именем ключа.

- **Cortex — прежний Sonar.** Имя видно только в двух строках перевода
  (`ai_btn`, `ai_title`) и берётся из бота, как все остальные. В коде
  приложения вкладка, экран и поле хранилища тоже зовутся Cortex; сохранённый
  выбор переносит миграция второй версии — иначе человек открыл бы приложение
  на чужой вкладке. Поле бутстрапа API отдаёт под обоими именами: приложение
  обновляется само, а whale_api перезапускают руками, и между этими двумя
  событиями свежая сборка обязана что-то прочитать. Старое имя убрать, когда
  все перезапустятся.
- **Ноль сделок — нет полосы.** Не деление на ноль и не `NaN%`.
- **Число алертов — из `me.alerts30d`.** Не вшитое `194` для всех.

Русский текст, который сервер собирает сам («покупка», «лонг 5×», «5 мин»),
разбирается в `lib/labels.ts` и `lib/relative.ts` и показывается на языке
интерфейса.

## Развёртывание

Контейнер — nginx со статикой; API живёт отдельно и подключается через
`API_UPSTREAM`.

| Переменная | Что делает |
|---|---|
| `PORT` | порт nginx, по умолчанию 8080 |
| `API_UPSTREAM` | адрес whale_api; без него прокси идёт в `127.0.0.1:8090` |
| `API_KEY` | общий секрет с API; пусто — порт API открыт всем |

У `whale_api.py` свои переменные — см. `whale-api.service`. Обязательны
`WHALE_TG_TOKEN` (без него служба не поднимется: проверять подпись нечем),
`WHALE_API_ORIGIN` (адрес мини-аппа, иначе браузер получит отказ по CORS) и
`WHALE_API_KEY` — тот же, что `API_KEY` у контейнера.

nginx и API стоят на разных машинах, между ними интернет. Поэтому
`WHALE_API_HOST=0.0.0.0`, а порт 8090 закрывают `WHALE_API_KEY` и firewall:
открой его только адресам Cloud Run.

**`API_UPSTREAM` задавай по HTTPS.** По HTTP через интернет уедут открытым
текстом и `X-Telegram-Init-Data`, и `X-Api-Key`.
