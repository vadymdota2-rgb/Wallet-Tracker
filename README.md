# Wallet Tracker Mini App — восстановленные исходники

## Зачем это

Приложение делали в конструкторе Grok. В репозиторий положили только
результат сборки — папку `html/`, где `routes.js` весит 400 КБ и состоит
из 72 строк с односимвольными именами. Исходников не сохранилось ни у
кого, поэтому любая правка означала писать вслепую внутрь сжатого файла.

Здесь тот же код, восстановленный в читаемом виде. Соответствие
минифицированных имён и модулей — в `BUNDLE-MAP.md`.

## Как собрать

```bash
npm install
npm run typecheck   # проверка типов без сборки
npm run build       # результат складывается в html/assets/
```

`build` сначала гоняет `tsc`, и только потом собирает: ошибка типов
останавливает сборку, а не всплывает у пользователя.

`emptyOutDir` выключен намеренно — в `html/` лежит папка `coins/` с
логотипами (~1500 файлов, 26 МБ), её сборка не должна стирать.

## Что уже дало восстановление

Дефекты, которых в сжатом коде было не увидеть:

- **Форматирование чисел.** Локаль `ru-RU` была вшита жёстко: разряды
  отделялись узким пробелом независимо от выбранного языка.
- **Строка мимо переводов.** Ошибка обновления показывалась по-русски
  всем шестнадцати языкам. Теперь это ключ `toastSyncFailed`.
- **Полоса «пульса».** При нуле сделок делила на ноль и пропадала.
- **Логотипы монет.** Запасной путь через Hyperliquid добавлялся только
  при пустом адресе контракта. У ZEC адрес есть — существует одноимённый
  токен на BSC, — и монета оставалась вовсе без иконки.
- **Мёртвая переменная** в компоненте иконки, остаток той же проверки.

## Устройство

```
src/i18n/       16 словарей, 6403 строки; ключи заданы английским
src/lib/        форматирование, типы API, запросы, отклик Telegram
src/store/      состояние: сохраняемое (useApp) и живое (useLive)
src/components/ строка, кнопка, заголовок, плитки, пульс, иконка монеты
src/screens/    экраны
src/styles/     стили
```

Ключи переводов привязаны к английскому словарю: пропустишь ключ в
переводе — сборка остановится и назовёт его. Раньше такой пропуск молча
превращался в английское слово.

## Чего здесь нет

Библиотеки, вшитые прежним сборщиком в `routes.js` — **sonner** (тосты,
~66 КБ) и **zustand** — вернулись зависимостями в `package.json`.
Собственного кода приложения оказалось около 75 КБ, а не 140.

## Сборка отличается от прежней

Прежний `routes.js` и `live.js` собирались **без хеша в имени**, а nginx
отдаёт `/assets/` как неизменяемые на год. После выката браузер брал
новый `app.js` вместе с прошлогодним `routes.js` и падал с «Unexpected
end of input». Здесь у всех файлов хеш в имени, и такое невозможно.

Из-за этого `html/index.html` после первой сборки будет ссылаться на
другие имена файлов. Прежние `app.js`, `routes.js`, `live.js`, `api.js`,
`store.js` и `styles-*.css` после проверки можно удалить.

## Состояние

Восстановление завершено. 74 файла, около 4400 строк кода плюс 6400
строк словарей.

src/store/       состояние: сохраняемое (useApp) и живое (useLive)
src/components/  13 компонентов, включая свечи и фон

## Как собрать

```bash
npm install
npm run typecheck
npm run build
```

Номер сборки берётся из переменной `BUILD_NUMBER`, иначе подставляется
дата. Раньше в меню было зашито число `27`.

## Что изменится после сборки

Файлы получат хеш в имени. Прежние `app.js`, `routes.js`, `live.js`,
`api.js`, `store.js` и `styles-*.css` станут не нужны — но удаляй их
только после проверки в Telegram.

Tailwind убран: его утилит в разметке не оказалось ни одной, тянулся он
ради сброса стилей и занимал 22 КБ. Вместо него короткий `reset.css`.

## Дефекты, найденные при восстановлении

Ни один не был виден в сжатом коде. Первые — обычные ошибки, последние
четыре серьёзнее: пользователю показывались выдуманные данные.

1. **Локаль `ru-RU` вшита в форматирование чисел** — разряды отделялись
   узким пробелом независимо от языка.
2. **Строка «Не удалось обновить» мимо переводов** — по-русски всем
   шестнадцати языкам.
3. **Язык принудительно ставился английским**, если не выбран вручную;
   выбор языка в боте игнорировался.
4. **`followTrader`** называл кошелёк `трейдер #N` по-русски.
5. **Подпись «вход» на графике** — тоже жёстко по-русски.
6. **Полоса «пульса»** делила на ноль при отсутствии сделок.
7. **Логотипы монет**: запасной путь через Hyperliquid добавлялся только
   при пустом адресе. У ZEC адрес есть — существует одноимённый токен на
   BSC, — и монета оставалась без иконки.
8. **Прибыль кошелька всегда зелёная**, даже при убытке.
9. **Запас до ликвидации** считался без проверки текущей цены: `NaN%`.
10. **Средняя прибыль трейдера** делила на ноль без сделок; отношение
    прибыли к просадке — при нулевой просадке.
11. **Произвольный порог** уходил на сервер как `NaN` при пустом поле.
12. **Список разделов рынка** описан не полностью: восемь вкладок, в
    перечислении пять.
13. **История сигналов** показывала нули как статистику, когда
    результатов ещё нет.
14. **Модель** для перпов всегда сообщала «не обучена» — флаг передавался
    жёстко.
15. **Номер сборки** зашит числом `27`.
16. **Мёртвая переменная** в компоненте иконки.
17. **Число алертов за 30 дней зашито как `194`** — одна и та же цифра
    показывалась всем пользователям.
18. **Cortex фильтровал сигналы по списку тикеров** (`BTC`, `SOL`,
    `CAKE`, `HYPE`) в зависимости от окна. Это не отбор по данным, а
    имитация.
19. **Топ трейдеров умножал показатели на выдуманные коэффициенты**:
    прибыль на 1.85, 2.7 и 3.9, доходность на 0.72, 0.58 и 0.44 в
    зависимости от выбранного окна. Сервер за этими окнами не ходил.
    Люди решали, за кем следовать, по несуществующим числам.
20. **График рисовал выдуманную историю**, когда котировки не пришли:
    32 точки линейной интерполяции между ценой входа и текущей. По виду
    обычный график, по сути ничего.

## Что проверить после первой сборки

- **Окна рейтинга.** Пункты 90, 180 и 365 дней помечены как без данных.
  Если сервер их не считает — либо доработать `whale_api.py`, либо
  оставить одно окно и убрать переключатель.
- **Сигналы Cortex.** Отбор идёт по полям `venue`, `win` и `side`. Если
  сервер их не заполняет, список окажется пустым — это правда, но
  требует доработки API.
- **Число алертов за 30 дней** берётся из `me.alerts30d`. Убедиться, что
  сервер его отдаёт.
